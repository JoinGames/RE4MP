# Выводы из полученного api4 и приложений

Источник — пользовательский `RE4MP_scout_api4.json`, версия сканера 4:
2259 объектов, 809 типов компонентов, 143 синглтона, 0 ошибок обхода.
Ключевые сигнатуры и SHA-256 исходного скана сохранены в
[evidence/api4-model.json](evidence/api4-model.json).

## Подтверждённые данные

- `CharacterManager.generateDynamicContextID()` возвращает новый ContextID.
  Это предпочтительнее ручного копирования/правки идентификатора игрока.
- `ContextID` наследует `chainsaw.AppObjectBase`: прежнее предположение handoff
  о простой value-type структуре не подтверждается.
- `requestCreateBody(ContextID, CharacterKindID, CharacterUsePurposeFlag,
  Action<ValueTuple<Int32,GameObject>>)` возвращает `Int32` request ID;
  `requestDestroyBody(Int32)` принимает номер запроса.
- `CharacterUsePurposeFlag.Dynamic = 2`, `Spawner = 1`.
- У `CharacterBodyUpdater` есть `get_InstanceDemandID()` и
  `get_InstanceParentID()`: они позволяют проверять принадлежность тела запросу.
- `CharacterContext` возвращает `BodyGameObject`, `KindID`, `SpawnerID`,
  `CostumePresetID` и текущую сцену через отдельные getters.
- `ControlTargets` содержит одного игрока с `ContextID.Code = 262148`,
  Category=0, Kind=0, Group=2, Index=4.
- `CharacterKindID.ch0_a0z0 = 100000`; это соответствует наблюдаемому
  локальному телу `ch0a0z0_body`. Другие enum присутствуют, но возможность
  создать соответствующий prefab в текущей сцене не проверена.
- `DoorSide.SideA = 0`, `SideB = 1`; значения полезны для будущей работы с дверями.

## Что показали файлы другого мода

Читаемый `shared.lua` ищет объект с именем `Player 2` и снимает ресурсы FSM
у слоёв 0, 1, 4 и 5 компонента `via.motion.MotionFsm2`. Он не содержит создания
объекта и не доказывает использование слота Эшли. Он также не задаёт, какие
анимации проигрывать вместо отключённых FSM.

`type_remaps_auto.json` содержит числовые таблицы для Ada, Ashley, Luis и
Leon (Merc). Их семантика из одного JSON не следует; это не подтверждённая
таблица значений CharacterKindID из скана. Подставлять эти числа в спавн нельзя.

Остальные шесть Lua-файлов сильно обфусцированы. Их внешняя структура не
раскрывает способ создания персонажей. Их код не исполнялся и не переносился
в наш мод; в репозиторий добавлена собственная реализация эксперимента.

## Чего пока не хватает

Сигнатура метода подтверждает его существование, но не пред-/постусловия.
Не установлено, достаточен ли отдельный запрос тела без головы и CharacterContext,
как отрабатывает nil callback и когда тело становится видимым/готовым к анимации.
Model Probe проверяет этот путь отдельным ручным опытом.

Scout v4 также обрезал часть данных: 600 из 1236 связанных типов и 90 полей
живого PlayerBaseContext. Поэтому в `live.player` нет базового ID/KindID;
ID удалось увидеть в ControlTargets. В новом отчёте нужные getters вызываются
напрямую, дополнительно собираются типы пулов и `via.motion`.

По скриншоту исходящая частота — 50.5 Гц при ~100 FPS; входящая 1.9 Гц.
Пользователь уточнил, что партнёр стоял и после обновления движение стало плавнее.
Это соответствует отправке раз в два кадра при движении и редким keepalive в покое.
