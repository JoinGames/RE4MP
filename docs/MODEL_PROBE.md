# Ручной тест визуального тела — v0.3.3

Цель: проверить, может ли `CharacterManager.requestCreateBody` создать отдельное
тело текущего персонажа и позволить выставлять его позицию. В тесте v0.3.0
создание объекта и запись/чтение позиции подтвердились, видимого персонажа не было.
В v0.3.1 Draw/DrawSelf включились, но модель не появилась. v0.3.2 исправила
обход дерева и загрузку костюма через CostumeManager. v0.3.3 оставляет тест
на 180 секунд, проверяет одежду и снимает боевые компоненты.
Видимость подтверждена, анимации и урон ещё не подтверждены.
Скрипт при загрузке ничего не создаёт. Тест запускается кнопкой, один раз за
сессию скриптов, и через 180 секунд запрашивает удаление тела.

## Установка и запуск

1. Закрой игру. Используй `RE4LAN.lua` версии 0.3.0 и замени
   `RE4LAN_ModelProbe.lua` версией 0.3.3 в `<игра>\reframework\autorun` на тестовом ПК.
   Удали из `autorun` дубли этих скриптов. Relay v0.2.1 подходит.
2. Запусти только наш мод, без одновременно активного стороннего мультиплеера.
   Его прикреплённые Lua-файлы для этого теста не нужны.
3. Запусти обычное соединение host/join или `start_echo.bat` для проверки в одиночку.
   Загрузи деревню, дождись видимой жёлтой фигуры и статуса `CONNECTED`.
4. Это пробное создание нативного объекта: используй отдельную тестовую сессию,
   не сохраняй игру во время опыта и перезапусти её после теста перед обычной игрой.
   Lua `pcall` не может гарантированно перехватить нативное падение движка.
5. Открой `Insert → Script Generated UI → RE4LAN Model Probe`.
   Сначала нажми **Capture model API (read-only)**. Эта кнопка только читает данные.
6. Нажми **TEST: create one visual body** один раз. После появления `active`
   подожди 3 секунды для исходных снимков отрисовки. Тело автоматически
   удаляется через 180 секунд.
   Если тело не найдено, через 15 секунд поиск завершится.
   Если тело появится, проверь поворот и короткое движение партнёра.
   В echo ожидаемая позиция находится на 3 метра по X от твоего игрока.
7. Нажми новую кнопку **TEST: apply local costume**. Подожди 10 секунд,
   сделай скриншот. Это отдельный нативный эксперимент: проверяется, может ли
   CostumeManager добавить геометрию к телу без связанного CharacterContext.
8. При необходимости нажми **TEST: follow cloth (teleport)** и подвигай второго
   игрока. Сравни, следует ли куртка за телом.
9. Нажми **Remove test body**. После запроса костюма очистка может ждать до
   15 секунд; при `cleanup_blocked` перезапусти игру.
   После запроса костюма сначала завершается его загрузка и запрашивается
   освобождение ресурсов. Подожди до 15 секунд; если `cleanup_blocked` или
   ошибка, закрой игру — тело намеренно не освобождается при незавершённой
   работе CostumeManager. Не используй Reset scripts для повторного теста.
   Удаление обрабатывает движок асинхронно — статус не доказывает, что тело исчезло.
   Перед следующим тестом перезапусти игру.

Если пока хочется только собрать данные, достаточно пункта 5.

## Что прислать

- `<игра>\reframework\data\RE4LAN_model_probe.json`;
- скриншот меню Model Probe и модели, если она появилась;
- наблюдение: тело видно/не видно, двигается/стоит, есть ли мешающие движения.

Отчёт автоматически обновляется до вызова создания, после нахождения тела,
после первой записи позиции, при замерах видимости и при остановке/ошибке. Если игра закрылась при
попытке создания, последний отчёт покажет, до какого шага дошёл скрипт.
При ошибке записи отчёта нужны строки `[RE4LAN Model Probe]` из `reframework.log`.

## Значения состояния

| State | Значение |
| --- | --- |
| `idle` | Создание не запрашивалось. |
| `requesting` | Записан отчёт перед вызовом `requestCreateBody`. |
| `waiting` | Получен номер запроса; ищем созданное тело с двумя совпадающими идентификаторами. |
| `active` | Тело найдено; проверен DrawSelf, выставляется поза. Видимость и анимации нужно оценить глазами. |
| `costume_cleanup` | Поза больше не записывается; ожидается освобождение ресурсов костюма. |
| `cleanup_blocked` | Освобождение костюма не подтверждено за 15 секунд; нужен перезапуск игры. |
| `removal_requested` | Вызван `requestDestroyBody`; завершение удаления пока не подтверждено. |
| `abandoned` | Сцена/игрок изменились; старые идентификаторы больше не используются. |
| `error` | Lua/API вернули ошибку; автоматического повторного создания нет. |

## Устройство эксперимента и ограничения

Используется шаблон уже загруженного локального персонажа, обычно Леона.
Выбора Ады/Эшли пока нет: наличие enum ещё не доказывает, что их ресурсы загружены.
Для нового тела игра выдаёт собственный `ContextID`; ID игрока не редактируется.
Код не вызывает `requestControl`, `requestSpawn`, создание головы/ИИ или запись
сохранения и не подменяет слот партнёра.

Найденное тело принимается только при совпадении `InstanceDemandID` с номером
своего запроса и `InstanceParentID` с собственным новым ID. Сам объект игрока
исключён. После присвоения уникального имени тело заново находится и проверяется
на каждом использовании; нативные объекты не сохраняются между кадрами.

В проверенном запуске `nil` callback не помешал создать объект тела. Это не
подтверждает обработку `nil` у нового вызова `CostumeManager.requestCostumeChange`.
Тело может остаться невидимым. FSM, коллизии и UpdateSelf скрипт не переключает.
Геометрию и связанные ресурсы по новому запросу настраивает сам CostumeManager.

При создании меняется только `DrawSelf` собственного корня, только если он `false`.
Повторного принудительного включения каждый кадр нет: если движок сбросит флаг,
это останется в отчёте. Флаги папок, предков и дочерних мешей скрипт не переключает;
переключение их флагов могло бы показать скрытые варианты костюма или другие объекты.

В `visuals` находятся снимки `before_draw`, `after_draw`, `after_1s`, `after_3s`
и `before_remove`. Для каждого узла записываются Draw/DrawSelf, Update/UpdateSelf,
масштаб, типы компонентов, доступные свойства мешей и наличие CharacterContext.
`mesh_count` — число компонентов мешей в успешно прочитанной части дерева,
а не доказательство загруженной геометрии. См. также `errors`, `children_error`
и `truncated`; при неполной выгрузке нулевой счётчик не доказывает отсутствие меша.
`local_visual` содержит аналогичный снимок настоящего игрока для сравнения.
`draw_change` показывает исходное/полученное значение и факт вызова setter.

v0.3.3 добавляет `position` каждого узла, Motion layers и `HitController`.
Для боевой диагностики используются только getters: `Context`,
`CurrentHitPoint`, `Invincible`, `AttackEnable`, `DamageToParent`, `Setuped`,
регистрация HitManager и наличие коллайдеров. Созданная копия с `Context=nil`
не считается готовым хитбоксом. Сетевой выстрел и изменение HP не выполняются,
пока не подтверждён связанный CharacterContext и безопасный игровой вызов.

v0.3.2 обходит настоящий `IEnumerable<Transform>` через перечислитель,
поддерживает явные реализации интерфейсов и ограничивает число прочитанных
детей. Используется подтверждённый `Mesh.getMesh()`, дополнительно читаются
`get_MeshReady` и `get_MaterialReady`. В `visuals` добавляются `before_costume`
и `costume_after_1s/3s/10s`. Раздел `costume` содержит номер пресета и состояние
очередей/реестра, включая удаление. Счётчики очередей глобальные: работа с
другим персонажем тоже может задержать очистку; чужие записи не удаляются.

Костюм запрашивается один раз, отдельной кнопкой, после проверки
`isExistAsset(kind, preset)` и доступности методов учёта ресурсов. Перед
`requestDestroyBody` должны опустеть очереди изменения/удаления костюма и
исчезнуть запись собственного тела в реестре. Это проверка состояния API,
а не доказательство корректной очистки всех внутренних ресурсов движка.

Новые методы и поля пула/движения собираются в `report.api`. В `local_player`
важные поля читаются напрямую, чтобы не потерять ID и KindID из-за общего
ограничения числа унаследованных полей в Scout v4.
