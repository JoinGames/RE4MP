# Проверка слота партнёра/Эшли — v0.1.0

Этот тест нужен, чтобы понять, как сторонний кооп-мод создаёт второго игрока.
Он только читает существующие объекты. Он не вызывает spawn/release, не меняет
Transform, MotionFsm2, оружие, урон или сохранение.

## Запуск

1. Закрой игру и скопируй `RE4LAN_PartnerContextProbe.lua` в
   `<игра>\reframework\autorun`. Оставь обычные `RE4LAN.lua` и relay как есть.
2. Запусти сторонний кооп-мод так, как обычно запускаешь игру с другом. Для
   этого одноразового теста не нажимай кнопки Model Probe и Linked Spawn Probe.
3. Загрузи игровой участок, дождись появления второго игрока или доступных
   кооп-действий и открой `Insert → Script Generated UI → RE4LAN Partner Context Probe`.
4. Нажми **Capture partner/Ashley slot** один раз. Перезапусти игру после
   сохранения отчёта; сам тест ничего не освобождает.
5. Пришли файл
   `<игра>\reframework\data\RE4LAN_partner_context_probe.json`.

В отчёте нас интересуют `contexts`, `game_objects`, `CharacterBodyUpdater`,
`HitController` и `Motion` layers. Если `contexts` пуст, но найден `Player 2`,
это означает, что обфусцированный мод создаёт только визуальный объект либо
использует другой менеджер. Если найден настоящий context, по его ID и типам
можно безопасно привязать сетевую позу, а затем отдельно проверить анимацию.

Не запускай эту кнопку одновременно на сохранении, во время катсцены или при
переходе между сценами. Отчёт read-only, но REFramework и сторонние плагины
могут менять сцену асинхронно; после сбора данных нужен обычный перезапуск.
